## What This Is

LEX FORENSICA is an axiomatic AI forensic pipeline — a self-governing system built to analyze text, events, and institutional conduct through a structured chain of rules that apply to both the subject being analyzed and to the system doing the analyzing.

It does not simply produce output. It **certifies output through its own law** before emitting it into the world.

The system reached its first major version summit on 2026-04-12 after a concentrated build phase beginning 2026-04-09. This post explains what was built, why it is structured this way, and where it stands now.

## The Core Idea

Most AI systems answer questions. LEX FORENSICA investigates them — and then investigates its own investigation.

This is the **circular cypher** at the heart of the architecture: the rules that judge institutions also judge the system itself. The pipeline runs in six sequential stages:

```
MIND1 → BRIDGE (SHA-256) → DEEP_1 → LOOP_CYCLE [12] → DEFENSE_SYNTHESIS
```

`MIND1` tokenizes and normalizes. `BRIDGE` hashes the output so tampering is detectable. `DEEP_1` runs deep inference with web search enabled. `LOOP_CYCLE` applies 12 axiomatic checks. `DEFENSE_SYNTHESIS` produces the final certified output.

If `LOOP_CYCLE` catches a critical violation, the pipeline re-runs — maximum twice — before escalating to human intervention. The system knows when to stop itself.

## The Directional Spectrum

The architecture is not a flat set of rules. It is a directed repair pipeline — moving from damage inward to live output outward:

```
[DAMAGE] → [WEIGHTS] → [OPERATION] → [REPAIR] → [ALIGN] → [LIVE]
  detect     measure     execute      reconstruct  cohere    follow
```

Every analysis enters at `DAMAGE` and must travel the full spectrum before becoming output. The live output carries the damage that made its conclusions necessary. This is what makes the system **forensic** rather than merely analytical.
